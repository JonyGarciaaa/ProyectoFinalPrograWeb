4. Resumen de Arquitectura y Tecnologías

El proyecto fue desarrollado utilizando una arquitectura desacoplada de tres niveles:

  • Frontend: React 19 estructurado con TypeScript y Vite. Para los estilos se implementó Tailwind CSS bajo diseño responsivo sin uso de plantillas prediseñadas. La gestión del estado de autenticación se maneja con React Context API y almacenamiento del token JWT.
  • Backend: API REST desarrollada con Node.js (versión 22) y Express 5 en TypeScript. El código está organizado bajo una estructura de capas: Rutas, Controladores, Servicios, Middlewares y Validadores. Las validaciones de datos de entrada se procesan mediante la librería Zod.
  • Persistencia de Datos: PostgreSQL versión 16 como sistema gestor de base de datos relacional y Prisma ORM para el acceso tipado a datos, migraciones y ejecución del sembrado inicial de datos (seed).
  • Seguridad: Cifrado de contraseñas mediante función hash bcryptjs con factor de coste de 10 rondas de salting; autenticación y autorización mediante tokens JWT en el encabezado Authorization; cabeceras HTTP configuradas con Helmet; y control de acceso basado en roles (RBAC).
  • Pruebas Automatizadas: Suites de pruebas unitarias y de integración para Backend (Vitest y Supertest) y Frontend (@testing-library/react) integradas en el pipeline de GitHub Actions.
  • Contenerización: Configuración multi-etapa con Docker y Docker Compose para la ejecución local de PostgreSQL, Backend y Frontend con Nginx.
5. Reglas de Negocio Validadas
  • RN-01: Un espacio no puede registrar dos reservaciones con traslape en la misma fecha y rango de horas. Condición lógica: (nuevaInicio < existenteFin) Y (nuevaFin > existenteInicio).
  • RN-02: Se requiere inicio de sesión y token JWT válido para crear una reservación.
  • RN-03: Un usuario únicamente tiene permisos para cancelar sus propias reservaciones activas.
  • RN-04: El administrador tiene acceso a consultar y actualizar el estado de todas las reservaciones.
  • RN-05: No se pueden realizar reservaciones sobre espacios marcados como deshabilitados.
  • RN-06: La hora de inicio de una reservación debe ser estrictamente menor a la hora de finalización.
  • RN-07: No se permite la creación de reservaciones para fechas pasadas respecto a la fecha actual del sistema.
  • RN-08: Cada reservación queda vinculada formalmente a un usuario y a un espacio existente.
  • RN-09: Los estados permitidos para una reserva son: PENDING, CONFIRMED, CANCELLED y COMPLETED.
6. Ejecución Local con Docker (Evaluación en Aula)

Para la revisión local del proyecto mediante contenedores, se requiere tener Docker Desktop en ejecución y utilizar el siguiente comando desde la raíz del repositorio:

docker compose up -d --build

Direcciones locales generadas:

  • Frontend Web: http://localhost:5173
  • Backend API: http://localhost:4000/api/health
  • PostgreSQL: puerto 5432
